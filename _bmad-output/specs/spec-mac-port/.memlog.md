topic: Port CTR Native to macOS (MacBook Air Apple Silicon arm64)
updated: 2026-11-18T12:18
---

- (decision) Target architecture: Native macOS on Apple Silicon (arm64, Darwin), supporting M-series processors (including user's MacBook Air M5)
- (constraint) macOS does not support 32-bit binaries (-m32); executable must build and run as native 64-bit (arm64)
- (constraint) macOS Mach-O linkers do not support GNU ld flags (-Wl,--image-base, -no-pie, --allow-multiple-definition, -static-libgcc); toolchain configuration must branch for Darwin
- (constraint) macOS arm64 kernel enforces 4GB __PAGEZERO; physical/virtual mapping at 0x1f800000 is invalid; Scratchpad RAM must be backed by a heap/static buffer and raw pointer literals refactored to CTR_SCRATCHPAD_PTR
- (constraint) 24-bit GPU primitive OT links (CtrGpu_PrimToOTLink24) cannot store 64-bit raw pointers; must use arena-relative 24-bit offsets or an arena bridge
- (capability) CAP-1: Build system produces a native macOS arm64 binary (ctr_native) using Apple Clang, CMake, and statically linked vendored SDL3
- (capability) CAP-2: 64-bit decoupled scratchpad memory subsystem backing PS1 scratchpad without fixed low-memory OS page requirements
- (capability) CAP-3: 64-bit compatible GPU primitive and ordering-table link bridge preserving 24-bit OT compatibility without pointer truncation
- (capability) CAP-4: Video, audio, and gamepad input functional on macOS via SDL3 Cocoa and CoreAudio backends with OpenGL 3.3 Core Profile
- (capability) CAP-5: Full gameplay parity running retail assets (BIGFILE.BIG) on macOS Apple Silicon without 64-bit alignment crashes
- (note) Created dedicated git branch mac-port for macOS port development
- (note) Non-goal: Native Metal or Vulkan backend rewrite; OpenGL 3.3 Core Profile provided by macOS OpenGL framework is sufficient
- (note) Non-goal: iOS/iPadOS or tvOS ports; scope is exclusively macOS Darwin on Apple Silicon
- (note) Non-goal: Running via 32-bit Wine or x86 emulator; the target is a native 64-bit arm64 Mach-O binary
- (assumption) Apple Silicon macOS includes OpenGL 3.3 Core profile support and Clang with C99 support via Xcode Command Line Tools
- (question) Should the build produce a standalone .app bundle (CTR Native.app) or a Unix CLI binary in build/ctr_native?
